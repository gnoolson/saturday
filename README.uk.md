**Платформа для IoT: виконуйте власну бізнес-логіку та керуйте пристроями за допомогою простих Lua-сценаріїв.**

**Saturday** — це готове середовище для автоматизації, обробки телеметрії та координації MQTT-пристроїв.

Замість ускладнення прошивок апаратного забезпечення, Saturday дозволяє винести всю загальну бізнес-логіку в окремий керований шар. Ви описуєте потрібну поведінку системи у вигляді легких Lua-скриптів, які можна змінювати в реальному часі — без перекомпіляції та перезапуску додатка.

#### Як це працює?
Saturday підключається до MQTT-брокера як клієнт, підписується на необхідні топіки та миттєво обробляє вхідні повідомлення за заданими Lua-сценаріями.

---

### Основні можливості

- Виконання бізнес-логіки в реальному часі: Миттєва обробка та маршрутизація MQTT-повідомлень.
- Власні HTML/CSS/JS Панелі: Створення веб-інтерфейсів для моніторингу та керування з можливістю передачі параметрів у сценарії.
- Гнучкі тригери та розклад: Запуск скриптів за Cron-розкладом, подіями MQTT, з панелі чи при виникненні помилок.
- Розширювана архітектура: Можливість додавати новий функціонал через систему плагінів.

#### Можливості Lua-середовища ("із коробки")
Зі сценаріїв Lua ви маєте вбудований доступ до:  
- Баз даних та кешування (для збереження стану й телеметрії);
- Telegram API (для сповіщень та інтерактивних команд);
- Роботи з Serial-портом та операційною системою;
- Взаємодії з плагінами та іншими сценаріями.

#### Тригери запуску сценаріїв
- MQTT: Отримання повідомлення за підпискою.
- Панель: Дія користувача у веб-інтерфейсі.
- Розклад: Автоматичний запуск (Cronонання бізнес-логіки в реальному часі:** Миттєва обробка...).).
- Плагіни: Внутрішні та зовнішні події.
- Мережа: Підключення чи відключення MQTT-клієнтів.
- Dev Mode: Ручний запуск для налагодження.
- Обробка помилок: Реакція на збої в інших сценаріях.

#### Для чого підходить?
Побудова систем автоматизації, IoT-інфраструктури, телеметрії, диспетчеризації обладнання та гнучких MQTT-інтеграцій.

### Системні вимоги
Saturday — це Java-додаток (JAR), для роботи якого потрібна **JRE 1.8** або новіша.  
*Споживання RAM (на прикладі `ibm-semeru-open-jre-21`): ~200–300 MB.*

---

### Запуск

#### Варіант 1: Через Docker (з готовим середовищем)
1. Перейдіть у розділ [Releases](https://github.com/gnoolson/saturday/releases) та завантажте архів `saturday-docker-***.zip`.
2. Розпакуйте архів у будь-який каталог.
3. Запустіть скрипт для вашої ОС:
   - **Linux:** `./start.sh`
   - **Windows:** `start.bat`
4. Відкрийте браузер за адресою `http://localhost:5050`.

*Щоб зупинити додаток, запустіть `./stop.sh` або `stop.bat`.*

#### Варіант 2: Як звичайний JAR
1. Перейдіть у розділ [Releases](https://github.com/gnoolson/saturday/releases) та завантажте архів `saturday-jar-***.zip`.
2. Розпакуйте архів у будь-який каталог.
3. Запустіть скрипт для вашої ОС:
   - **Linux:** `./start.sh`
   - **Windows:** `start.bat`
4. Відкрийте браузер за адресою `http://localhost:5050`.


### Збірка проєкту з вихідного коду
- Збірка **Docker**-образу: `sh/docker_build.sh` (треба вказати `JRE_FOLDER` в сценарії)
- Збірка **JAR**: `sh/jar_build.sh`

*Результат збірки буде в каталозі `_dist`.*

Для збірки потрібно щоб каталог проєкту `saturday` був в одному каталозі з проєктом [saturday-plugins](https://github.com/gnoolson/saturday-plugins).

### Демо-проєкти
Одразу після першого запуску вам будуть доступні декілька демонстраційних проєктів, які на практиці показують, як влаштована та працює **Saturday**.
За замовчуванням усі демо-ресурси вимкнені. Щоб задіяти їх після першого старту:
- Більше -> MQTT Брокер -> Увімкнути
- Сценарії -> Увімкнути (усі сценарії)
- Клієнти -> Підключити (усі клієнти)
- Розклади -> Увімкнути (усі розклади)
